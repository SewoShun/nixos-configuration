# Spec: Noctalia から eww 中心のデスクトップシェルへの移行

Status: ready-for-agent

関連: ADR-0001（eww と単機能ツールでデスクトップシェルを組む）、ADR-0002（デスクトップシェルはキーボードだけで操作する）。用語は `CONTEXT.md` に従う。

## Problem Statement

デスクトップシェルを Noctalia Shell（`legacy-v4` ブランチ固定）1 つに任せているため、見た目を細部まで自分の好みに作り込めない。また、設定 GUI・カレンダー・壁紙などの使っていない機能まで抱えていて重い。キーバインド、swayidle のロック、起動処理がすべて Noctalia の IPC に依存しているので、部品を 1 つだけ差し替えることもできない。

## Solution

デスクトップシェルを部品ごとに分け、それぞれを単機能の道具に任せる。

- **バー・ポップアップ・OSD**: eww で自作し、yuck/scss で見た目を作り込む。
- **ランチャー**: anyrun（Rust 製）。
- **セッションメニュー**: wleave（Rust 製）。
- **ロック画面**: swaylock。
- **通知**: dunst（現状維持）。

配色はすべて catppuccin の flavor に追従させる。操作はすべてキーボードで行い、マウス操作は作らない。移行は段階的に進め、どの段階で `nh os switch` してもデスクトップが使える状態を保つ。最後に Noctalia のモジュールと flake input を削除する。

## User Stories

### ランチャー

1. ユーザーとして、`Mod+d` で anyrun を開きたい。Noctalia がなくてもアプリを名前で検索して起動できるようにするため。
2. ユーザーとして、anyrun はアプリケーション検索だけを出してほしい。余計な機能がない、軽いランチャーにするため。
3. ユーザーとして、anyrun の配色を catppuccin の flavor に合わせたい。デスクトップシェル全体の見た目を揃えるため。
4. ユーザーとして、anyrun のフォントは ZedMono Nerd Font にしたい。バーや OSD と書体を揃えるため。
5. ユーザーとして、anyrun をキーボードだけで操作して閉じたい（`Esc` で閉じ、`Enter` で起動）。マウスに手を伸ばさずに済むようにするため。

### セッションメニュー

6. ユーザーとして、`Mod+Shift+p` で wleave を開きたい。ロックや電源操作をメニューから選べるようにするため。
7. ユーザーとして、wleave にはロック・ログアウト・サスペンド・再起動・電源オフを並べたい。セッションの終わらせ方を 1 か所で選べるようにするため。
8. laptop のユーザーとして、wleave にハイバネートも出してほしい。logind で既に使っている操作をメニューからも選べるようにするため。
9. desktop のユーザーとして、wleave にハイバネートを出してほしくない。使わない選択肢で迷わないようにするため。
10. ユーザーとして、各ボタンを頭文字のキー（l / e / s / h / r / p）で選びたい。キーボードだけで素早く操作するため。
11. ユーザーとして、wleave のロックが swaylock を呼んでほしい。どこからロックしても同じロック画面になるようにするため。
12. ユーザーとして、wleave のログアウトで niri を終了したい。greetd の画面に戻るため。
13. ユーザーとして、wleave の見た目を catppuccin に合わせたい。テーマを統一するため。

### ロック画面

14. laptop のユーザーとして、無操作のまま一定時間が経ったら swaylock でロックされてほしい。席を離れたときに画面を守るため。
15. laptop のユーザーとして、スリープに入る直前に swaylock でロックされてほしい。復帰したときにロックされた状態になっているようにするため。
16. ユーザーとして、swaylock の背景を awww と同じ壁紙にしたい。ロックを解除する前後で見た目が途切れないようにするため。
17. 保守する人として、壁紙のパスを 1 か所で定義したい。壁紙を変えたときに、awww と swaylock の背景が食い違わないようにするため。
18. ユーザーとして、swaylock の配色を catppuccin に合わせたい。テーマを統一するため。
19. laptop のユーザーとして、swayidle は niri と swaylock の両方が有効なときにだけ動いてほしい。Noctalia を削除したあともロックが働き続けるようにするため。

### バー（共通）

20. ユーザーとして、すべてのモニターの左端に縦置きのバーを出したい。どのモニターを見ていても状態が分かるようにするため。
21. ユーザーとして、バーが画面上の領域を予約し、ウィンドウがバーに重ならないようにしたい。
22. ユーザーとして、バーの配色を catppuccin の flavor に追従させたい。flavor を変えたらバーの色も変わるようにするため。
23. ユーザーとして、バーのフォントは ZedMono Nerd Font にしたい。アイコンを表示でき、等幅で数字の幅が揃うようにするため。
24. ユーザーとして、バーをクリックやスクロールしても何も起きないことを了解している。デスクトップシェルはキーボードだけで操作する方針だから（ADR-0002）。
25. ユーザーとして、ログインしたら自動でバーが表示されてほしい。手で起動しなくて済むようにするため。
26. ユーザーとして、eww が落ちても自動で再起動され、ログを `journalctl --user` で見られるようにしたい。問題を調べやすくするため。

### バー：ワークスペース

27. ユーザーとして、バーには、そのバーが乗っているモニターのワークスペースだけを番号で並べてほしい。niri のモニターごとのワークスペースと対応させるため。
28. ユーザーとして、アクティブなワークスペースを強調表示してほしい。いまどこにいるかが一目で分かるようにするため。
29. ユーザーとして、ウィンドウがあるワークスペースと空のワークスペースの見た目を変えてほしい。どこに作業があるかが分かるようにするため。
30. ユーザーとして、キーボードでワークスペースを移動したら、バーの表示がすぐ追従してほしい。表示が古いまま残らないようにするため。
31. ユーザーとして、ワークスペースが増えたり減ったりしたら、バーの表示もそれに合わせて変わってほしい。

### バー：日付と時刻

32. ユーザーとして、バーに月・日・時・分の順で縦に並べて表示してほしい。カレンダーがなくても日付と時刻が分かるようにするため。
33. ユーザーとして、日付の前にカレンダーのアイコン、時刻の前に時計のアイコンを出してほしい。数字だけが並んでも日付と時刻を区別できるようにするため。
34. ユーザーとして、日付と時刻の文字の大きさと色は同じにしたい。

### バー：音量・輝度・バッテリー・ネットワーク・トレイ

35. ユーザーとして、バーに現在の音量とミュート状態を表示してほしい。
36. ユーザーとして、音量キーや他のアプリで音量を変えたら、バーの表示が追従してほしい。
37. laptop のユーザーとして、バーに現在の輝度を表示してほしい。
38. desktop のユーザーとして、輝度の表示は出してほしくない。バックライトがないから。
39. laptop のユーザーとして、バーにバッテリーのアイコンと残量の % を表示してほしい。
40. laptop のユーザーとして、充電中はバッテリーのアイコンを変えてほしい。充電中かどうかが分かるようにするため。
41. desktop のユーザーとして、バッテリーの表示は出してほしくない。バッテリーがないから。
42. ユーザーとして、ネットワークの状態（有線、Wi-Fi の電波強度の段階、切断）をアイコンだけで表示してほしい。幅の狭い縦置きのバーに収まるようにするため。
43. ユーザーとして、システムトレイのアイコンを主モニターのバーにだけ表示してほしい。常駐しているアプリが見えるようにするため（操作はしない）。
44. desktop のユーザーとして、主モニターを DP-1 にしたい。
45. laptop のユーザーとして、唯一のモニターである eDP-1 が自動的に主モニターになってほしい。

### OSD

46. ユーザーとして、音量キー（上げる、下げる、ミュート）で音量を変えたい。
47. laptop のユーザーとして、輝度キーで輝度を変えたい。
48. ユーザーとして、音量キーや輝度キーを押したら、画面下の中央に OSD を出してほしい。変更後の値をすぐに確認できるようにするため。
49. ユーザーとして、OSD にはアイコン、ゲージ、% を表示してほしい。
50. ユーザーとして、ミュート中は OSD のアイコンを変え、ゲージを灰色にしてほしい。ミュートしていることがすぐ分かるようにするため。
51. ユーザーとして、最後にキーを押してから約 1.5 秒で OSD が消えてほしい。
52. ユーザーとして、キーを連打している間は OSD を出し続けてほしい（消えるまでの時間を延長する）。途中でちらつかないようにするため。
53. ユーザーとして、キー操作以外で値が変わったとき（pavucontrol で音量を変えたときなど）は OSD を出さないでほしい。予期しないときに表示されないようにするため。
54. ユーザーとして、OSD がフォーカスを奪わないでほしい。入力中の作業を邪魔されないようにするため。

### ポップアップ

55. ユーザーとして、`Mod+Shift+m` でシステムモニターのポップアップを開きたい。
56. ユーザーとして、もう一度 `Mod+Shift+m` を押したらポップアップを閉じたい。
57. ユーザーとして、ポップアップに CPU 使用率、メモリ、ディスク、温度を表示してほしい。
58. ユーザーとして、ポップアップがフォーカスを奪わないでほしい。開いたままでも作業を続けられるようにするため。
59. ユーザーとして、ポップアップの配色とフォントをバーと揃えたい。

### キーバインドの整理

60. ユーザーとして、`Mod+Comma`（Noctalia の設定画面）を削除したい。設定は宣言的に書くので、設定画面は不要だから。
61. ユーザーとして、`Mod+c`（カレンダー）を削除したい。日付はバーに出るから。

### 移行と保守

62. 保守する人として、移行のどの段階で `nh os switch` しても、デスクトップが使える状態を保ちたい。移行を何日かに分けて進められるようにするため。
63. 保守する人として、移行の最後に Noctalia のモジュール、niri からの参照、flake input をすべて削除したい。使われない依存を残さないようにするため。
64. 保守する人として、eww の yuck、scss、スクリプトをリポジトリ内の普通のファイルとして管理したい。エディタの補完やハイライトを使えるようにするため。
65. 保守する人として、eww が使うスクリプトの依存（jq、niri、wpctl、brightnessctl など）を Nix で固定したい。PATH の違いで動かなくなる事故を防ぐため。
66. 保守する人として、スクリプトが shellcheck を通ることをビルド時に確かめたい。
67. 保守する人として、eww・anyrun・wleave・swaylock をそれぞれ独立した denix モジュールにして、`features.gui` から有効にしたい。既存のモジュールと同じ書き方に揃えるため。
68. 保守する人として、catppuccin の flavor を変えるのは 1 か所だけで済ませたい。eww と anyrun の配色を含め、デスクトップシェル全体が追従するようにするため。

## Implementation Decisions

### モジュール構成

- denix モジュールを新しく 4 つ作り、`features.gui` から有効にする。いずれも既存と同じ `delib.singleEnableOption false` の形にする。
  - **`programs.eww`**: バー、ポップアップ、OSD を担当する。
  - **`programs.anyrun`**: ランチャー。
  - **`programs.wleave`**: セッションメニュー。
  - **`programs.swaylock`**: ロック画面。
- **`programs.niri`** のキーバインドと `spawn-at-startup` は、これまでどおり `homeConfig.programs.<tool>.package` を参照して各ツールを呼ぶ。Noctalia の IPC を呼ぶヘルパーは削除する。
- **`services.swayidle`** の lock コマンドを swaylock に替える。**`hardware.laptop`** での swayidle の有効条件は `niri && swaylock` に変える。desktop には今回も swayidle を入れない。
- **`programs.noctalia-shell`** モジュール、`features.gui` での有効化、flake input は移行の最後に削除する。
- dunst は変更しない。

### ホストの情報

- `myconfig.host.displays` の各要素に、任意の属性 **`primary`**（真偽値）を追加する。desktop では DP-1 に付ける。
  - `primary` が付いたディスプレイがなければ、先頭のディスプレイを主モニターとみなす。laptop は eDP-1 が自動的に主モニターになる。
- 「輝度とバッテリーがあるホストか」は **`hardware.laptop` が有効かどうか**で判定する。

### 共有する値

- **壁紙**: パスを 1 か所で定義し、awww（niri の起動処理）と swaylock の背景の両方から参照する。現在の値は `nixos-artwork` の `nineish-catppuccin-mocha-alt`。
- **フォント**: デスクトップシェル共通で ZedMono Nerd Font を使う（既にシステムに入っている）。
- **配色**: catppuccin の palette JSON から `myconfig.catppuccin.flavor` に対応する色を取り出す生成器を 1 つ作る。出力は次の 2 つ。
  - eww 用の SCSS 変数ファイル
  - anyrun 用の GTK CSS の色定義
- wleave と swaylock は catppuccin/nix の自動テーマに任せる。

### eww

- **設定ファイル**: yuck、scss、スクリプトはリポジトリ内の普通のファイルとして置き、`xdg.configFile` で Nix ストア経由で配置する。
  - home-manager の `programs.eww.configDir` は非推奨なので使わない。
  - `yuckConfig`/`scssConfig` だけでは複数のファイルを配置できないので、`xdg.configFile` を使う。
  - 配色の SCSS とホストごとの差分（輝度とバッテリーを出すか、主モニターの名前、モニターの一覧）は Nix で生成し、同じディレクトリに置く。
- **起動**: `programs.eww.systemd.enable` でデーモンを `graphical-session.target` に紐づける。ウィンドウ（各モニターのバー）は niri の `spawn-at-startup` から開く。
- **バーのウィンドウ**: モニターごとに 1 つずつ作り、左に縦置きして、`exclusive` で画面の領域を予約する。上から次の順に並べる。
  - ワークスペース
  - 日付と時刻（カレンダーアイコン、月、日、時計アイコン、時、分）
  - 音量
  - 輝度（laptop だけ）
  - バッテリー（laptop だけ）
  - ネットワーク
  - トレイ（主モニターだけ）
- **ワークスペース**: スクリプトが `niri msg --json event-stream` を購読する。そのモニターのワークスペースについて、インデックス、アクティブかどうか、ウィンドウがあるかどうかを JSON にして `deflisten` に流す。
- **音量**: PipeWire の変化を購読する `deflisten` で取る。キー操作以外で値が変わってもバーの表示は更新するが、OSD は出さない。
- **輝度とバッテリー**: 輝度は brightnessctl から、バッテリーは eww の組み込み変数 `EWW_BATTERY` から取る。
- **ネットワーク**: NetworkManager（`nmcli`）から、有線、Wi-Fi の電波強度の段階、切断のいずれかを取る。
- **システムモニターのポップアップ**: フォーカスを取らないウィンドウにする。eww の組み込み変数 `EWW_CPU`、`EWW_RAM`、`EWW_DISK`、`EWW_TEMPS` を表示する。`Mod+Shift+m` で `eww open --toggle` する。
- **OSD**: フォーカスを取らない、画面下の中央のウィンドウにする。キーバインドからは OSD 用のスクリプトを呼ぶ。スクリプトの流れは次のとおり。
  1. `wpctl` または `brightnessctl` で値を変える
  2. eww の変数（種類、値、ミュート状態）を更新する
  3. OSD を開く
  4. 約 1.5 秒後に閉じる
  - タイマーは、キーを押すたびにリセットされる（連打している間は延長される）。
- **マウス操作**: マウスで反応する部品（`:onclick` や `:onscroll` など）は作らない（ADR-0002）。
- **スクリプト**: すべて bash と jq で書き、`writeShellApplication` でパッケージにする。依存は `runtimeInputs` で固定する。

### キーバインド

| キー | 変更後 |
|---|---|
| `Mod+d` | anyrun |
| `Mod+Shift+p` | wleave |
| `Mod+Shift+m` | eww のシステムモニターのポップアップを開閉 |
| 音量キー（上げる、下げる、ミュート）、輝度キー（上げる、下げる） | OSD 用のスクリプト |
| `Mod+Comma`、`Mod+c` | 削除 |

輝度キーは全ホストで共通のまま残す。desktop では押しても何も起きない。

### anyrun と wleave

- **anyrun**: home-manager の `programs.anyrun` を使う。プラグインは `applications` だけにする。CSS は配色の生成器が出力した色を使う。
- **wleave**: home-manager の `programs.wleave` を使う。ボタンとキーの割り当ては次のとおり。
  - lock → swaylock（`l`）
  - logout → `niri msg action quit`（`e`）
  - suspend（`s`）
  - hibernate（`h`、laptop だけ）
  - reboot（`r`）
  - shutdown（`p`）

### 移行の順序

各段階が終わった時点でデスクトップが使えることを前提にする。

1. ロック画面（swaylock）と swayidle の付け替え
2. ランチャー（anyrun）
3. セッションメニュー（wleave）
4. eww の基盤（モジュール、配色の生成、systemd での起動、ホストごとの差分）
5. OSD とメディアキーの付け替え
6. システムモニターのポップアップ
7. eww バーの導入と、Noctalia のバーの停止
8. Noctalia の完全な削除

Noctalia と eww のバーが同時に表示される期間は作らない。eww のバーを有効にするのと、Noctalia の起動をやめるのは同じ段階で行う。

## Testing Decisions

- **良いテストとは**: 外から観察できる振る舞いだけを確かめるもの。この構成では次の 2 つを指す。
  - 両ホストのシステムがビルドできること
  - 実機で、決めたとおりに見えて決めたとおりに動くこと
- **自動の確認（唯一のシーム）**: `nixosConfigurations.desktop` と `nixosConfigurations.thinkpad-e14-gen7` の `config.system.build.toplevel` がビルドできること。これで次のことがまとめて確かめられる。
  - Nix の評価エラーがないこと
  - `writeShellApplication` による shellcheck が通ること
  - 生成した配色ファイルとホストごとの差分ファイルが組み立てられること
  - 削除したモジュールや flake input への参照が残っていないこと

  前例として、PR ごとに CI の nix-diff ワークフローが同じ 2 つの属性をビルドしている。ローカルでは各チケットの最後に両ホストの `toplevel` をビルドする。
- **手動の確認**: 各チケットに受け入れ用のチェックリストを書く。`nh os switch` したあと、laptop と desktop の実機で確かめる（desktop だけ、laptop だけに関わる項目はそのホストで確かめる）。
  - eww は表示中のディスプレイがないと yuck や scss を検証できないので、見た目と操作は手動で確かめる。
- **作らないもの**: headless のコンポジタ上で eww を起動して検査する flake check や、スクリプト単体のテスト。

## Out of Scope

- 通知デーモンの変更（dunst のまま）。
- バッテリー残量が少ないときの警告通知。
- GPU（NVIDIA）の使用率の表示。
- カレンダーのポップアップ。
- バーでのウィンドウタイトルの表示、Bluetooth の表示、fcitx5 の入力モードの表示。
- マウス操作（ADR-0002）。システムトレイのメニュー操作も含む。
- desktop への swayidle の導入。
- 壁紙の管理（awww のまま）と greeter（regreet のまま）の変更。
- eww の設定ファイルをストアを経由せずにリンクして、ホットリロードすること（ストア経由で配置すると決めた）。

## Further Notes

- `legacy-v4` の Noctalia は自前で通知を受け取る機能を持っている可能性があり、dunst と D-Bus の名前を取り合っているかもしれない。Noctalia を削除したあと、dunst が通知を受け取ることを手動で確かめる項目に入れる。
- niri のワークスペースのイベントの JSON の形は niri のバージョンに依存する（`niri-unstable` を使っている）。スクリプトは niri のバージョンを上げたときに壊れやすいので、問題が起きたらまずここを疑う。
- catppuccin/nix は wleave と swaylock には対応しているが、eww と anyrun には対応していない。この 2 つの配色は生成器だけが頼りになる。
